# Model card — SPINE adapter

## Intended use

Converts free-text network-operations reports (alert emails, syslog fragments,
chat messages, ticket notes) into a strict JSON incident record, or abstains when
the text is not an actionable incident. Intended as a pre-parser in front of a
ticketing or automation system, with the JSON schema enforced downstream.

## Not intended for

- Any decision made without a human in the loop. `action_required` is a
  suggestion extracted from the text, not an operational judgement.
- Vendors, event types or severities outside the closed vocabularies in
  `src/spine/schema.py`. The model has no way to express an event it has no
  label for except `unknown`.
- Text in languages other than English, or real production logs with formats not
  represented in the six synthetic surface styles.

## Training data

Fully synthetic, generated by `src/spine/data/synth.py` from a facts-first
pipeline. ~6,000 training examples, ~17% abstain cases, six surface styles (two
held out for OOD evaluation), five vendor dialects. No real customer data, no
scraped logs, no PII. Hostnames, sites, ticket IDs and IP addresses are generated.

**The consequence of synthetic data is the main limitation of this model.** Real
NOC text is messier, multilingual in places, and contains failure modes the
generator does not model (interleaved threads, truncated pastes, screenshots
described in prose). Numbers on this test set are an upper bound on real-world
performance, not an estimate of it.

## Evaluation

See `docs/RESULTS.md`. Headline metric is exact match on the full normalised
record; the suite also reports schema validity, per-field accuracy, interface F1,
refusal precision/recall, and a verbatim-grounding check on `evidence_span`.

## Known failure modes

- Timezone conversion when the offset is named (`IST`, `CET`) rather than numeric.
- Distinguishing a stated severity from an implied one when the text carries both.
- Long forwarded email chains where the incident is quoted rather than reported.
- Abstain phrasings that superficially resemble alerts (resolved-notices, planned
  maintenance) — the two hardest classes in the abstain pool.
